# ATT / V2 — button + funnel audit

**Date:** 19 Aug 2026 · **Scope:** `auto-ai-frontend` (V2 rebuild) only.
**Method:** real clicks in headless Chromium against the **production build**
(`npm run build` → `vite preview`), not code review. 201 controls clicked across
16 routes, 52 screenshots captured.

This is a **findings pass. Nothing here was fixed.**

---

## 0. What "live" means for this audit — read first

There is **no deployed ATT URL to click.** Vercel, queried from this session,
returns exactly one project for the account: `chachy-hunter-core`. No
`auto-ai-frontend` project is reachable, and none was created (creating one is
not authorised).

So "live" here means **the real production bundle** — the same artifact a deploy
would serve — served locally. Every result below is a real click on real built
output. What this audit **cannot** tell you: whether a deploy exists elsewhere,
and whether anything backend-dependent works, because egress to
`*.supabase.co` is blocked from this session.

## 1. THE HEADLINE — the entry funnel dead-ends

**Every route into the product terminates at an empty `<div>`.**

There are exactly three ways a visitor can try to get in. All three go to the
same place:

| Control | Where | Goes to | What is actually there |
|---|---|---|---|
| "Enter Founder OS →" | landing hero | `/#access` | an empty, **0-pixel-tall** div |
| "Request access" | site header | `/#access` | same empty div |
| Wake Zayra orb (signed out) | every page | `/#access` | same empty div |

Clicking "Enter Founder OS" scrolls the page 806px down and lands the visitor on
the **"What Zayra is" marketing section**. Screenshot: `verify-access-funnel.png`.

**There is no access flow at all.** Verified by counting form inputs:
`input[type=email]` count is **0** on every page, at every one of the five
viewports in the house device standard. No signup, no sign-in, no waitlist, no
email capture. `/login` does not exist.

The orb is more specific about it: its accessible label is literally **"Sign in
to talk to Zayra"**, and it writes `auth_return_url` to localStorage — verified,
it stored `/founder?step=1` — a return URL saved for an auth flow that does not
exist.

**Consequence:** the funnel converts nobody, on any device. Everything below is
secondary to this.

## 2. THE SECOND FINDING — `/empire` claims 7 features are AVAILABLE. 5 are not.

Zayra Home renders a "Private Alpha Status" card with a green-ticked
**AVAILABLE** list. Verbatim, as rendered:

> AVAILABLE — ✓ Founder Engine · ✓ Zayra Cloud · ✓ Zayra Media · ✓ Entity Draft
> Prep · ✓ Lawns & Trees Proof-of-Concept · ✓ Zayra Platform Guide · ✓ Founder
> Scholar Q&A

Checked against this surface:

| Claimed AVAILABLE ✓ | Reality on V2 |
|---|---|
| Founder Engine | **Partly true** — 2 of 11 stages have forms |
| Entity Draft Prep | **Partly true** — stage 4 prepares a draft |
| Zayra Cloud | **FALSE** — `/zayra-cloud` renders "This screen hasn't been ported yet" |
| Zayra Media | **FALSE** — `/zayra-media` renders the same placeholder |
| Lawns & Trees Proof-of-Concept | **FALSE** — does not exist anywhere in this app |
| Zayra Platform Guide | **FALSE** — does not exist anywhere in this app |
| Founder Scholar Q&A | **FALSE** — does not exist anywhere in this app |

**Five of seven availability claims are false on this surface.** This was ported
from V1, where they may well be true. Here it directly contradicts the promise
the landing page makes three sections earlier — *"Features are labelled by what
is actually wired up. Nothing is described as live before it is."*

This is a **house-law violation, not a gap.** It is the one finding in this
report that is actively misleading rather than merely absent.

The **LOCKED** half of the same card is correct and should stay: Live Filing,
Payments, Trading, Auto-Posting, Admin Tools — all genuinely locked, matching
the alpha locks.

## 5. The founder funnel, run end to end

Stage 1 was driven as a real founder would: type → confirm → submit → reload.

| Step | Result |
|---|---|
| Renders 3 fields | PASS |
| Submit disabled on empty form | PASS |
| Submit still disabled when filled but unconfirmed | PASS |
| Spelling gate appears once a legal field has a value | PASS |
| Submit **enables** after confirming | PASS |
| **Editing a confirmed field re-locks submit** | PASS — the law holds under a real click |
| Submit produces a visible result | PASS |
| **Data survives a reload** | **FAIL — nothing persists** |

Persistence was checked directly: after reload, **0 fields repopulated,
localStorage `[]`, sessionStorage `[]`.** A founder who fills in stage 1 and
refreshes loses everything. Same for stage 4.

**Stage 4 (Formation)** — all correct: 5 fields, 4 legal-string spelling gates
(`formationState` correctly not gated), submit enables only when all 4 are
confirmed, and the "Live filing is locked" banner renders as designed.

**Stage coverage: 2 of 11.** Only steps 1 and 4 have real forms. Steps 2, 3,
5–11 render a placeholder.

**Bad input is handled** — `?step=abc`, `?step=99`, `?step=-4` and `?step=`
all render a valid stage rather than crashing. The NaN clamp holds.
